# 维护公开源码

公开仓库和保留原版文件的开发仓库使用独立 Git 历史。日常开发可编辑 `overlay/` 的自有模块，或先在私有开发工作区验证，再将审阅后的改动同步回来。需要重新导出时，在新的公开候选目录中运行 `python tools/export_overlay.py --private-repository <本地开发仓库>`。已有覆盖目录不会被覆盖。

客户端补丁保存输入与输出的 SHA-256，以及插入内容。旧文件只从本机基底读取。更新补丁时复核改动来源，尤其是带原版引用的 Unity 资源。原版或基于原版加工的模型、皮肤、字体、音频、表数据和程序集继续放在本地。

提交前先检查 `git status --short`，再运行 `python tools/check_public.py` 和 `git diff --cached --check`。用一次干净克隆和自备基底验证 `hydrate` 与 `build-server`。正式客户端的发布包、安全签名、用户存档和原版资源都留在本机。

原版资源处理的三个步骤可单独运行。更换 APK、热更新资源或 AssetRipper 版本容易改变导出的 GUID 和反编译文本。要支持新的本地基底，先对照补丁输入校验，再单独验证 Unity 场景引用及启动。保存兼容版本记录和修复步骤即可。
