# 原创剧情制作流程

## 先写整章，再拆关

1. 确定本章承接的前情、人物当下想办的事、他最不愿面对的事，以及最后做出的选择。主线继续第 52 章之后的事件。角色、专武和助手服装各有独立的获取线。
2. 按实际游玩顺序列出每关的地点、战斗目标、剧情前后发生的变化和奖励。有信息或人物决定的关卡才安排对白。截哨、守桥、清理援兵等可以用纯战斗关交代。
3. 固定每关敌方卡牌和波次。强度按出战练度在关卡配置的上下限内浮动。同一关至少试两套打法，确认低稀有度队伍能靠先控、拆后排或续航等方式过关。
4. 角色招募、装备坯和服装放在一次性首通。通篇后可开放高难魔王扫荡，给专属碎片或原锻造配方实际消耗的材料。记录小队完成首通、做出第一件以及整套毕业所需的时间。

## 按用途准备美术

每个发生地分别考虑**可滑动的章节地图、对白布景和战斗场地**。先检查项目中的授权素材能否表达这个地点。缺少匹配素材时用内置 ImageGen 自行生成，同时保存原始提示词和成品。需要人物从卡框露出或做多层视差时，另生成带透明通道的人物或近景层。

战斗底图以接近 16∶9 的横幅为基础，地面向前延伸，画面下半部和中央留给双方卡牌、血条及角色技能。关卡发生在山桥、山门或锻室时，分别在环境中交代地点特征。把亮源放在边缘或远处，前后层次用雾、光和边缘细节表现。现有原创战斗模板可加载不同底图，并保留镜头微动和独立薄雾层。白桦林还有单独的透明近景。

成品 PNG 和 Unity 的 `.meta` 一起放进 [LocalStoryArt](../Project/Assets/Resources/LocalStoryArt)。新增支线逐关在 [LocalStoryCatalog.json](../Project/Assets/Resources/LocalStoryCatalog.json) 填写 `BattleArt`，使用 PNG 文件名去掉后缀。章节地图用 `MapArt`。原版敌方波次模板由 `TemplateId` 和可选 `WaveIds` 指定。关卡的前置由 `PreviousStage` 指定，认领阶段和扫荡阶段用各自现有的奖励字段。

## 用主线播放器做小模型对白

在 [LocalStoryDialogue.json](../Project/Assets/Resources/LocalStoryDialogue.json) 用 `Stage` 对应关卡 ID。战前对白写入 `Before`，战后对白写入 `After`。每句记录 `Speaker` 和 `Text`，可用 `Motion` 调用原版说话手势。现成可用的动作有指示（11）、抱臂（10）、行礼（12）、低落（14）和紧张（15）。省略该字段即使用默认说话表现。需要新角色时在 [LocalStoryDialogue.cs](../Project/Assets/Scripts/Assembly-CSharp/LocalStoryDialogue.cs) 对应一个已有原版 NPC 或可用的小模型资源，并实测说话时的朝向和动作。对白场景最多安排三名 NPC 与主角同场。

一句只表达一个意图。把人物心理写进他说漏的话、反复确认的细节和最后改变的决定。音效可用原版进场声和场景音乐，当前新对白采用无配音的原生字幕。首胜后有 `After` 的支线播放收尾，对白结束回到对应篇章。纯战斗关用 `BattleOnly`，点击以后直接开原版战前界面。

## 实机验收

- 先运行 `python Verification/verify_story_content_data.py` 检查台词、动作、底图文件和导入元数据。
- 用独立试玩存档核对章节切换、战前对白、纯战斗、战后对白、跳过、战败退出、扫荡和重进后的进度。确认战斗中实际加载的是对应关卡的 `BattleArt`，并在普通窗口、宽屏与手机比例检查牌和血条是否清楚。
- Windows 试玩分别用 `Start-Hong-Preview.cmd`、`Start-Maknae-Preview.cmd` 和 `Start-Chapter53-Preview.cmd`。完整 PC 路线回归用 `python Verification/launch_chapter53_preview.py --hong --verify`、`--maknae --verify` 和 `--verify`。发正式版前另测 Android 真机触控、画质及旧存档迁移。
